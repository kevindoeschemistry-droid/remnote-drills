# remnote-drills — Claude instructions

Kuta-style drill plugin for RemNote ("Wiki Sync", plugin id `wiki-sync` — never change the id: RemNote keys the card map, streaks and PDF links to it).

- Skill graph: `drills/skills.yaml` (skills), `drills/sources/*.yaml` (textbooks), `drills/courses/*.yaml` (courses), `drills/problems/*.yaml` (problems as data, preferred for numeric multi-step drills; verified by `tests/verify/data.py`; templates may draw `cases`, carry a `figure` drawn by `src/drills/fig-data.ts`, and mark a definitional key `verify: { authored: true }`, which means nothing recomputes it). See README for how to add a skill.
- Generators/checkers: `src/drills/`. Build problems backward from clean answers; check answers by property, never by string match.
- Every generator change: `npm test` (JS checker + negative controls + KaTeX over every template × 30 seeds, then an independent sympy verifier). Numeric engineering answers need a first-principles case in `tests/verify_sympy.py` (`heat_expected`), not a copy of the generator's formula.
- `npm run build` → `dist/` + `PluginZip.zip`. Local dev: RemNote → Plugins → Build → Develop from localhost (port 3005). Published as an unlisted plugin via Build → Upload plugin.
- Bump `version` in both `package.json` and `public/manifest.json`.
- CI (`.github/workflows/build.yml`) runs the version check, type check, `npm test` and the build on every push and PR, and keeps `PluginZip.zip` as an artifact. Release: bump the version, merge, then `git tag v<version> && git push origin v<version>`; the tag build attaches `PluginZip.zip` to a GitHub Release for Build → Upload plugin.
- `wiki:` links in `drills/sources/*.yaml` are checked against `drills/wiki-pages.json` on every `npm run skills`; a dead link fails the build. After the wiki's textbook pages change, refresh the snapshot with `node scripts/check-wiki.mjs --wiki <wiki repo>`.
- Standards: the house standard is our own objective codes; outside standards are what it is checked against. Every framework needs a `basis` (primary / also / wanted, ids from `drills/standards.yaml`), and units, topics or objectives cite outside items with `std: ["fe-chemical:7.F"]`. `npm run skills` fails on a missing basis or an unknown item and rewrites `docs/coverage/standards.md`. Never label a standard `read: full` unless its own text was read; a rulebook or a textbook is not a curriculum standard. How to grow it: `docs/standards.md`.
- Find the basis first. Before building a framework or a new family of items, look for a published standard, exam specification or curriculum to anchor it on, read it, and register it in `drills/standards.yaml`; keep looking for better bases for frameworks that rest on a weak one (the list is at the bottom of `docs/coverage/standards.md`). When nothing published exists, say so and label the list as a house decision.
- Variation matrices (`drills/matrices/*.yaml`, report in `docs/coverage/matrices.md`). A review set built from the homework covers only the versions the homework showed; the CBE 200 PDE midterm (Nov 2026) asked nonzero boundary values and the Laplace transform on the heat equation, and the review set had neither. Before writing a review or exam-prep set, write the grid first: every method the course names against every condition it could be asked under (boundary type, zero or nonzero, geometry, domain). Each cell lists its templates or states a `gap`; the build fails on an empty cell. Tell Kevin which cells are open before the exam, not after. When he passes on an instructor's topic list, every item on it gets its own cells.
- Pace. RemNote is for quick recall, so a review should be short. A problems-as-data template can declare `pace: recall` (about 10 s) or `quick` (under a minute); unmarked templates are guessed (one question = quick, several parts or a coded generator = workout). The warm-up mix has an "Under a minute" filter, and once a template has three timed first-try answers (`src/drills/times.ts`) the measured median overrides the declared pace. New items should be one question and `recall` or `quick` unless there is a reason; mental-math items (`mm-*`, framework `mental-math`, on the UIL Number Sense chart) must never be workouts. Estimates use `tol: 0.05`, the UIL rule.
- Anchor quantities (`aq-*`, framework `anchor-quantities`): magnitudes to know cold. No chemistry standard lists them, so units 1–4 are a house list; computable values must be checked against the constants in `tests/verify/data.py` (`CONST`, `calc(...)`), and a recall item accepts a band (`tol` may be an expression such as a case field).
- Draw this (`draw: true` + `solution:` figure, answer kind `self`): self-graded items for producing a graph, construction or structure from memory. One drawing, under a minute, and the prompt names the features that must match. Structures are `type: molecule` figures laid out by `scripts/mol.py` (RDKit, dev only) with a stated `formula` that `tests/verify/molecules.py` recomputes; that check cannot tell isomers apart, so look at every new structure once. `drills/problems/bc-amino-acids.yaml` and `st-structures.yaml` are generated from the tables in `scripts/mol_amino.py` and `scripts/mol_library.py` (`python3 scripts/mol.py --amino-acids` / `--library`): edit the table, not the YAML, and write each row's formula by hand so the generator can cross-check the SMILES. Mechanisms (`st-mechanisms.yaml`, from `scripts/mol_mech.py`, plain Python) are series of hand-laid states in which atoms stay put and only bonds and hydrogens move; a `molecule` figure takes `arrows` (curved, atom or bond ends) and `notes`, and a `scheme` stacks states. Every state of a mechanism must state the same formula and charge, which is how a dropped atom is caught. Small mechanisms (SN2, E2, HX addition, acyl substitution) are built by `small_mechanisms()` in the same script; a carbocation is a vertex labelled `C+`, which the checker counts as three bonds. Framework `structures` (ST) holds them; its compound list is a house list on Bruice's chapter order. The panel's reveal-and-mark flow cannot be tested here, so say so when it changes.
- DAT Perceptual Ability (`dat-pat.yaml`, generated by `scripts/pat_cases.py`, plain Python): angle ranking, hole punching, cube counting (figure type `cubes`) and cube nets. Each answer is computed twice by different methods, once in the generator and once in `tests/verify/data.py` (`rank_code`, `punch_count`, `cube_tally`, `net_opposite`, `view_identify`, `keyhole_fit`); keep the two implementations separate. Top-front-end views and keyholes come in the test's own four-lettered-drawings format (`pat-view-missing-*`, `pat-keyhole-pick`, checkers `view_missing`, `keyhole_pick`) on cube stacks (figure type `views`; grids may be packed as `1abcdefghi`), and on prisms with sloped faces (figure type `prism`, profile packed in hex, checkers `prism_identify`, `prism_keyhole`). A missing-view answer is unique because the checker enumerates every stack that shares the two given views. Curved solids and solids sloped in two directions are not built. Look at the rendered figures after any change to `prism`: its painter's-order drawing is only eyeballed.
- Predict the product (`rx-reactions.yaml`, generated by `scripts/mol_rxn.py` through `python3 scripts/mol.py --reactions`; framework `organic-reactions`, OR): each row states the reactant, reagents, product and, separately, what the reagents add or remove (`+HBr`, `-H2`); the generator refuses a product that does not mass-balance, which catches wrong atom counts but not regiochemistry or stereochemistry, so render and look at every new row. Reasoning rules are in `rx-reasoning.yaml` (`or-*`), engineering scaling in `eg-scaling.yaml` (`sc-*`, each verified as a ratio of the governing equation before and after the change, never from the exponent). A `choice:` must be a literal list; options that vary by case go in case fields (`o1`…`o4`) written as `["{{o1}}", …]`. In template `correct:` expressions compare numbers only: mathjs cannot compare strings, so give a case a numeric code beside any string field.
- Second question types. An objective with one template is drilled, not learned: K-8 had 229 of 258 objectives on a single type (the algorithm). When adding to a framework, prefer a second type on an existing objective (by inspection, in reverse, as a comparison, as an estimate, as a scaling) over a first type on a marginal one; `mx-strategies.yaml`, `mx-second-types.yaml`, `mm-subtraction.yaml` and `eg-scaling.yaml` are the pattern. The Types column in `docs/frameworks/README.md` is the measure.
- Checking a subset locally. `npm test` takes over 20 minutes. To check new items only: run `npx tsx tests/run.ts` to the end first (it writes `tests/out/problems.json`; if it crashes, the file is stale and a subset run will silently check the old problems, which is how `Integer` went missing from the verifier's names and failed CI on PR 42), then filter that file to the new templates and run `python3 tests/verify_sympy.py`. Confirm the problem count matches the number of new templates × 30. The five simulation stages between the checker and the verifier (`library-sim`, `library-choice-sim`, `path-view-render`, `warm-sim`, `static-sim`, each a few seconds) must also pass: `static-sim` rejects a raw `$` in card text (write "dollars"), which failed CI on PR 46. The verifier requires the template's reference answer to agree to one part in a million, so a `value:` must use the same constants as the verify expression (1239.841984 eV·nm, not 1240) and a given must not be named `x`, which the verifier uses as its symbol. Verify expressions may only use names in `BASE` (`tests/verify/data.py`): no builtin `max`, `min` or `int` (use `Max(*xs)`, `Min(*xs)`), and a case field must not share a name with a part label; a `solve` on an exponential with float-derived rationals can hang, so prefer a closed form there.
- Periodic table (`pt-periodic.yaml`, generated by `scripts/pt_cases.py`; framework `periodic-table`, PT): numbers, groups, triads, d and f counts, and self-graded write-the-row items. The generator's element list is flat; `tests/verify/data.py` keeps its own copy by period (`pt_Z`, `pt_group`, `pt_below`), so edit both or the check fails. Ground-state configurations (`pt-config-*`) are typed atom by atom in the generator and rebuilt in the verifier from the filling order plus its own exception list (`pt_config`, `pt_madelung`); both were written from memory, so check a new entry against NIST. Group 3 below yttrium is never asked.
- Sound: `src/drills/sound.ts` synthesises the right-answer ding and the went-warm flourish with Web Audio (no files, no network; setting `drill-sound`). It cannot be tested here, so say so when it changes.
- SQL (`sq-query.yaml`, `sq-manage.yaml`; framework `sql`, SQ, on Oracle 1Z0-071): cards are in Oracle SQL on the six-row tables typed in `tests/verify/sql.py` (`TABLES`). The verifier runs each statement on SQLite after `_translate` (MINUS, FETCH FIRST, DUAL, DATE literals, DML aliases) with Oracle's functions added in Python, through `sql_val`, `sql_count`, `sql_pick`, `sql_list`, `sql_match`, `sql_after` and `sql_fails`. Where SQLite would answer differently (NULL sort order, ANY/ALL, nested aggregates, DDL commits, MERGE, INSERT ALL) the case carries the verifier's own query or script (`vq`, `vw`, `vo`, `vs`) written another way. A table drawn on a card is a `scheme` panel captioned with the table's name, and the verifier fails if its rows differ from `TABLES`. Choice options may now contain `_ % & #`: the answer's `\text{}` escapes them.
- AI basics (`ab-basics.yaml`; framework `ai-basics`, AB): units follow the ten module titles of Harper Carroll's free Academy course, the only part of it readable (the lessons sit behind sign-up), so the objectives are ours. Arithmetic items (neuron, softmax, temperature, parameter counts, memory, precision and recall, cost, 6ND compute) are verified by sympy; facts are authored. If Kevin passes on her lesson list, map lessons to objectives and change the standard's `read` to match.
- Accounting (`fa-far.yaml`; framework `accounting-far`, FA, track `business`): one objective per FAR blueprint group (`cpa-far`, read through the 2024 edition's group titles; the 2026 PDF could not be fetched). US GAAP. Inventory cost flow is verified by `fa_inventory` in `tests/verify/data.py`, a unit-by-unit queue kept separate from the hand-written answers; bond and lease values are verified as explicit sums of discounted payments, not the annuity formula the card uses. AUD, REG and the discipline sections are not built.
- Programming (`pr-java.yaml`, `pr-python.yaml`; framework `programming`, PR): cards show code as a `code` figure (`src` names a case field, taken raw so braces are never read as fills; long lines shrink the font) and ask what it prints. `tests/verify/progcode.py` runs every snippet: Java as the body of main() through `java Main.java` (helpers or nested classes in `defs`; an uncaught exception prints its class name), Python in a fresh `python3 -I`; multi-line output is compared with " / " between lines. CI installs JDK 21 for this. Keep code lines under about 60 characters. Verify expressions cannot call `str()`: put the exact code or call in a case field.
- Computer science (`cs-core.yaml`; framework `computer-science`, CS2023): answers are hand-worked; `tests/verify/csalgo.py` recomputes traces with its own implementations (BFS/DFS/Kahn/Dijkstra/Kruskal on graphs written "a-b:3" or "a>b", neighbours alphabetical; BST orders, heap arrays, probing, Huffman, brute-force LCS/knapsack/coins, page replacement, a unit-step CPU scheduler, CIDR, longest prefix, FD closures and candidate keys); fork() cards compile and run C (`c_lines` in progcode.py, unbuffered stdout). In prompts, compare numbers only: give string-valued case fields a numeric code (`kn`, `an`) for ternaries.
- Multivariable calculus (`mvd-depth.yaml`, generated by `scripts/mvd_cases.py`; Calculus units 12–14, grid `drills/matrices/mvc.yaml`): each template carries many shapes (regions, curves, surfaces), not one problem with new numbers. The generator answers along the route the card teaches (Green, Stokes, divergence, polar, spherical); `tests/verify/mvcalc.py` checks along another (the line or surface integral itself, Cartesian limits by `quad`, which is nested numerical quadrature: split a region at its corners rather than writing Max/Min limits). Setup cards show four integrals; exactly one equals the target, asserted in the generator and re-checked by `vpick`. After regenerating YAML run `npm run skills` before `tests/run.ts`, or the verifier reads the old bundle.
- Final answers. A number answer accepts any expression with the right value unless it is marked `final` (`final: true` on a part, or `exact(v, label, true)` in a coded generator): then only one number counts (integer, decimal or p/q), so the arithmetic has to be done. Every `mm-*` template is final automatically. Use it wherever the arithmetic is the skill.
- Nursing (`nr-calc.yaml`, `nr-rules.yaml`; framework `nclex-rn`, NR, track `health`, on the 2026 NCLEX-RN Test Plan, `ncsbn-nclex-rn`): units are the plan's eight Client Needs subcategories. Dosage, IV and titrated drips, safe-dose ranges, MAP, Parkland, the 4-2-1 rule and I&O are verified by sympy; ABGs, ABO/Rh compatibility, GCS, APGAR and rule-of-nines scores by the separate tables in `tests/verify/nursing.py`, which read the card's own descriptions. Priorities, delegation, precautions, antidotes, levels and therapeutic communication are authored: standard entry-level content only, and where practice varies say "usual". NGN case-study formats are not built.
- Dentistry (`dn-calc.yaml`, `dn-rules.yaml`; framework `inbde`, DN, on the JCNDE Domain of Dentistry, `jcnde-domain`): units 1–3 are the three clinical sections, unit 4 is FK3 (dental materials, Kevin's interest; he sits on ADA SCDP committees, so expect him to check it). Tooth notation is verified against a list of teeth in `tests/verify/dental.py`, not the generator's arithmetic. Materials methods (ISO 4049 flexural strength, depth of cure, water sorption) were written from memory of the methods; the standard's text was not read.
- Helper modules in `tests/verify/` (any new `*.py` there) are loaded by `verify_sympy.py` as checkers and must define `check(p, H)` returning None; without it every coded-generator problem errors (PR 58). A subset run over data templates never reaches that path, so after adding a module run the subset on one coded template too (e.g. `^sep-`).
- Finals depth (Nov 2026). Everything lives in the Library frameworks, never in a course-only deck: a course file and a grid only point at Library objectives. `scripts/ht_final_cases.py` → `ht-final.yaml` (fins with convective or fixed tips and effectiveness, one-term cylinders and spheres, semi-infinite flux and convection, radiation-cooled lumps, solar and multimode surfaces, FD boundary nodes, tubes in an external fluid, fouling, transient mass diffusion, plates with an unheated start or uniform flux), checked by `tests/verify/htcalc.py` (dsolve on the fin ODE, orthogonality integrals, numerical integration, per-node control volumes); `scripts/pde_final_cases.py` → `pde-final.yaml` (time-varying boundaries, sources, cylinders with a nonzero wall, spheres, residue inversion, ghost nodes, implicit and Crank–Nicolson), checked by `tests/verify/pdecalc.py`. Grids `drills/matrices/heat-transfer.yaml` and `pde-1d.yaml` have no open cells. Engineering Math unit 10 is scaffolded from separation up to those problems; keep existing objective codes when restructuring (the Library's RemNote ids are keyed by code) and append new letters. The grid validator now knows coded generators too. To find drills outside the Library, compare every template in `tests/out/problems.json` with the drills the frameworks list.
- Choice order. A choice built entirely from case fields (`["{{o1}}", …]`) is shuffled per problem, so authors can write the right answer anywhere; a literal list (Low / Normal / High, Stage I–III, Class I–VI) keeps its order. The verifier still checks the template's own index.
- Thermodynamics depth (`scripts/td_cases.py` → `td-depth.yaml`, checked by `tests/verify/tdcalc.py`): every TD objective now has a drill. Verify expressions are evaluated with case fields as locals, so a comprehension or generator inside one cannot see them (`name 'P' is not defined`): put sums over case lists in a helper (`wsum`, `gibbs_S`). Equal-area and coexistence problems bisect on pressure; `findroot` on the two volumes is not reliable.
- Reaction engineering to Fogler 5e ch. 18 (`scripts/re_cases.py` → `re-depth.yaml`, checked by `tests/verify/recalc.py`; grid `drills/matrices/reaction-engineering.yaml`). Units 5–8 and the later letters of units 1–4 are a house list on Fogler's chapter order (no standard goes past FE area 12). Avoid `mpmath.odefun` in verifiers (minutes per case at 30 digits); `recalc._rk4` in floats is enough for the 1e-6 check. Case fields named `S`, `E`, `C`, `D`, `Y` collide with names in the verifier's namespace (`S` is the parser); use `Sc`, `Ea`, `Cc`, `Dl`, `Yx`. A `choice` option is rendered as text, so no `$…$` inside one.
- Science breadth standards (Nov 2026): NGSS HS, IB Chemistry/Physics/Biology 2025, USNCO, IChO (Appendices C–D and the 12-section syllabus), ACS ACCM, PE Chemical, GRE Physics and GRE Chemistry (discontinued, coverage check only) and part of the MCAT outline are registered with honest `read` levels and cited at unit level; the open items and what each would take to build are in `docs/standards.md` (Science breadth). Unit citations measure breadth, not depth: olympiad problems need their own harder items even where an AP unit is cited. A bare `std` code is credited to the framework's primary standard when that standard lists it, and an item without `parts` is itself a citable item.
- Inorganic and analytical chemistry (Nov 2026; frameworks `inorganic-chemistry` IN and `analytical-chemistry` AN, on IChO Appendices C–D): `scripts/in_cases.py` → `in-inorganic.yaml`, `scripts/an_cases.py` → `an-analytical.yaml`, both checked by `tests/verify/incalc.py`. Generators answer from typed tables and closed forms; the verifier recomputes by rule (oxidation states by charge balance with F, group 1–2, H, O and halide rules; d count = group − oxidation state; orbital filling for spin and CFSE; stereoisomers by enumeration over the octahedral or square rotation group with chelates as cis edges; unit cells from atom positions; titrations by electrons to the final reduced form) or from `FACTS`, a second table of colours, tests and oxide character that must agree with the generator's. Sources: Harris QCA 10e (chapter titles checked) and Miessler 5e (chapters 8–10 from memory). `tests/run.ts` checks the number of sources: bump it when adding one.
- Earth and space, relativity, Lagrangian mechanics, polymers (Nov 2026): `scripts/es_cases.py` writes `es-earth-space.yaml` (framework `earth-space`, ES, on NGSS HS ESS), `ph-relativity-lagrange.yaml` (physics units 29–30, scope extension) and `mt-materials.yaml` (framework `materials`, MT), all checked by `tests/verify/escalc.py`: force balance for orbits, the dimensionless Planck maximum for Wien, nsolve energy balances for climate, dsolve for decay ages, Lorentz boosts and rapidities, `sympy.euler_equations` for Lagrangian cases (linearise with a derivative at 0; `series` fails on function symbols), weight fractions for polymer averages, group counting for Carothers. Factual picks are checked against `ES_FACTS`, a second table.
- Separations and process design (Nov 2026; frameworks `separations` SP and `process-design` PD, on FE Chemical areas 10, 13, 15, 16 and PE Chemical 6.B and 7): `scripts/pd_cases.py` → `sp-separations.yaml`, `pd-design.yaml`, checked by `tests/verify/sepcalc.py` (Fenske by bisection on α^N r_B = r_D, minimum reflux from the pinch on the q-line, Kremser by solving the fraction-absorbed equation, explicit NPV sums, year-by-year depreciation and compounding, dsolve for first-order response). Sources Seader 3e, Turton 5e and Seborg 4e are chapter-mapped from memory.
- Chemistry olympiad layer (Nov 2026; framework `chemistry-olympiad` CO, on USNCO bands and IChO Appendix C): `scripts/oly_cases.py` → `co-olympiad.yaml`, checked by `tests/verify/olycalc.py`. Equilibria are solved exactly in both (mpmath bisection on the charge balance in the generator; sympy nsolve or log bisection in the verifier); cycles by solving Hess equations; isotope patterns and NMR lines by enumeration; decay chains by dsolve on the linear system. When registering a verifier module, grep for the module name, not a short alias: `grep -q "_CO"` matched another name and silently skipped the registration.
